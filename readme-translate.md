# README: как переводить русские строки на английский

Этот файл описывает полный цикл перевода интерфейса Icon Theme Toolkit. Процесс состоит из трёх больших этапов: сбор новых русских строк, их перевод, слияние в translations.txt и пересборка английской версии. Каждый этап можно запускать отдельно, но обычно их делают подряд.

## Структура каталогов

```
git/icon-theme-toolkit/                ← английская версия (результат)
├── icon-theme-toolkit.js              ← сюда попадает результат перевода
├── theme.js
├── settings.js
├── icon-compiler.js
├── winico2linuxtheme.js
├── ...
└── .git/                              ← отсюда делаем коммиты

git/icon-theme-toolkit-rus/            ← русская версия (источник)
├── icon-theme-toolkit.js              ← здесь правим русские строки
├── theme.js
├── settings.js
├── icon-compiler.js
├── winico2linuxtheme.js
├── translations.txt                   ← словарь пар «русский → английский»
├── translate.awk                      ← замена + сбор непереведённого
├── untranslated.txt                   ← (генерируется) список новых русских строк
├── translated.txt                     ← (создаём вручную) английские переводы
├── dupes.txt                          ← (генерируется) дубликаты в translations.txt
├── conflict.txt                       ← (генерируется) конфликты при слиянии
├── paste_translations.awk             ← слияние untranslated + translated
├── paste_trans.sh                     ← обёртка с проверками
└── build-en.sh                        ← прогоняет translate.awk по всем файлам
```

**Важно**. Все команды ниже выполняются из каталога git/icon-theme-toolkit-rus/, если не указано иное.

# Этап 1. Собрать новые русские строки

## 1.1. Убедиться, что все файлы на месте

Откройте терминал и перейдите в каталог русской версии:

```bash
cd ~/git/icon-theme-toolkit-rus
ls *.js *.awk *.sh translations.txt
```

Вы должны увидеть:

```
icon-theme-toolkit.js  theme.js  settings.js  icon-compiler.js  winico2linuxtheme.js
translate.awk  paste_translations.awk  paste_trans.sh  build-en.sh
translations.txt
```

Если translations.txt нет — создайте пустой: touch translations.txt.

## 1.2. Запустить build-en.sh

Этот скрипт прогоняет translate.awk по всем пяти JS-файлам, кладёт результат в ../icon-theme-toolkit/ и попутно собирает untranslated.txt и dupes.txt.

```bash
./build-en.sh
```

Что произойдёт:

· В ../icon-theme-toolkit/*.js появятся английские версии (с заменой всех известных пар).
· В untranslated.txt — список русских строк, для которых перевода ещё нет. Каждая строка — один фрагмент, без дублей.
· В dupes.txt — если в translations.txt есть один русский ключ с разными английскими переводами, они попадут сюда. Формат: пары «русский / английский», внутри группы — одна пустая строка, между группами — две.

## 1.3. Проверить untranslated.txt

```bash
cat untranslated.txt
```

Если файл пуст — все русские строки уже переведены, переходить к этапу 4 не нужно. Если не пуст — это и есть ваш список на перевод.

Совет. Если строк много, откройте untranslated.txt в редакторе (nano untranslated.txt или gedit untranslated.txt), чтобы было удобнее.

## 1.4. (Опционально) Разобрать dupes.txt

Если dupes.txt не пуст, в translations.txt есть дубликаты — один русский ключ, разные английские варианты. Это не ошибка (например, «Отмена» может быть и Cancel, и Abort в зависимости от контекста), но со временем translations.txt разрастается.

```bash
cat dupes.txt
```

Решение оставляете за собой: открываете translations.txt, находите нужную русскую строку и удаляете лишние варианты, оставляя один. Пока не трогайте — вернётесь к этому, когда translations.txt станет слишком большим. translate.awk всегда использует первый встреченный вариант для замены, так что дубликаты не ломают сборку.

Этап 2. Перевести untranslated.txt → translated.txt

## 2.1. Открыть untranslated.txt и скопировать содержимое

```bash
cat untranslated.txt
```

Скопируйте всё содержимое (выделить мышью + Ctrl+Shift+C).

## 2.2. Вставить в онлайн-переводчик

Подойдёт любой, который сохраняет построчное соответствие (одна строка на входе → одна строка на выходе). Хорошо работают:

· Google Translate — translate.google.com, режим «текст», направление «русский → английский». Вставляете блок, получаете блок.
· DeepL — deepl.com/translator, аналогично.
· Яндекс.Переводчик — translate.yandex.ru.

Важно. Некоторые переводчики склеивают короткие строки или разбивают длинные. После вставки в переводчик проверьте, что количество строк совпадает с исходным. Если нет — переводите блоками по 10–20 строк, чтобы сохранить соответствие.

## 2.3. Сохранить перевод в translated.txt

Создайте (или перезапишите) файл translated.txt:

```bash
nano translated.txt
```

Вставьте перевод (Ctrl+Shift+V), сохраните (Ctrl+O, Enter, Ctrl+X).

Требования к translated.txt:

· Ровно столько же непустых строк, сколько в untranslated.txt.
· Никаких пустых строк-разделителей между переводами — только сами переводы, по одному на строку.
· Порядок строк точно соответствует порядку в untranslated.txt: первая строка translated.txt — перевод первой строки untranslated.txt, и т.д.

Пример. Если untranslated.txt:

```
Отмена
Сохранить
Файл не найден
```

то translated.txt:

```
Cancel
Save
File not found
```

## 2.4. Проверить соответствие количества строк

```bash
grep -c -v '^[[:space:]]*$' untranslated.txt
grep -c -v '^[[:space:]]*$' translated.txt
```

Числа должны совпадать. Если нет — вернитесь к переводу и найдите пропущенную/лишнюю строку. paste_trans.sh откажется работать при несовпадении, так что лучше поправить сейчас.

Этап 3. Слить untranslated.txt + translated.txt в translations.txt

## 3.1. Запустить paste_trans.sh

```bash
./paste_trans.sh
```

Что произойдёт:

· Скрипт проверит наличие файлов, их непустоту, совпадение количества строк.
· Сделает резервную копию translations.txt (translations.txt.bak.YYYYMMDD-HHMMSS).
· Пропустит пары, которые уже есть в translations.txt с тем же переводом (дедупликация).
· Пропустит пары, где русский ключ уже есть, но перевод другой, и запишет их в conflict.txt.
· Добавит в конец translations.txt только новые пары.
· Выведет статистику: сколько пропущено как дубликаты, сколько конфликтов, сколько добавлено.

Пример вывода:

```
Резервная копия: translations.txt.bak.20251031-153000
Пропущено (уже есть с тем же переводом): 3
Пропущено (конфликт перевода, см. conflict.txt): 1
Будет добавлено новых пар: 12
Готово. Новых пар добавлено: 12.
Размер 'translations.txt': 245 непустых строк.
```

## 3.2. Если появился conflict.txt

```bash
cat conflict.txt
```

В файле — группы пар «русский / английский». В каждой группе:

· первая пара — уже существующий перевод из translations.txt;
· вторая пара — новый перевод, который вы только что прислали, но он был проигнорирован, потому что ключ уже занят.

Решите, какой вариант оставить:

· Если существующий перевод правильный — просто удалите conflict.txt: rm conflict.txt.
· Если новый перевод лучше — откройте translations.txt, найдите русскую строку и замените английский вариант на новый. Затем удалите conflict.txt.

Совет. conflict.txt можно игнорировать, если вы уверены, что старый перевод лучше. Скрипт специально не меняет существующие пары, чтобы случайно не «перекинуть» строки в собранных JS-файлах. Решение всегда за вами.

## 3.3. Очистить временные файлы (опционально)

После успешного слияния untranslated.txt и translated.txt можно очистить, чтобы при следующем прогоне не переводить их заново:

```bash
> untranslated.txt
> translated.txt
```

(> без команды слева очищает файл. Это безопасно.)

---

Этап 4. Пересобрать английскую версию

## 4.1. Запустить build-en.sh ещё раз

```bash
./build-en.sh
```

Теперь translate.awk применит обновлённый translations.txt ко всем JS-файлам, и в ../icon-theme-toolkit/*.js окажутся английские версии со всеми новыми переводами.

## 4.2. Проверить, что кириллицы не осталось

```bash
grep -nP '[\x{0400}-\x{04FF}]' ../icon-theme-toolkit/*.js || echo "Кириллицы не найдено — всё переведено."
```

Если grep ничего не нашёл — отлично. Если нашёл — значит, какие-то строки не попали в translations.txt. Проверьте untranslated.txt (он должен быть пуст после этапа 3.3) и при необходимости повторите этап 1–3.

Примечание. grep -P работает в GNU grep. На BSD/macOS используйте grep -n '[А-Яа-яЁё]'.

## 4.3. Проверить, что английская версия запускается

```bash
cd ../icon-theme-toolkit
gjs icon-theme-toolkit.js
```

(Или cjs icon-theme-toolkit.js, если вы на Cinnamon.) Убедитесь, что интерфейс открывается, вкладки работают, тексты на английском. Закройте окно.

# Этап 5. Закоммитить изменения

## 5.1. В русском репозитории

```bash
cd ~/git/icon-theme-toolkit-rus
git status
```

Вы увидите изменения в translations.txt, untranslated.txt (возможно, пуст), dupes.txt (возможно, пуст), translated.txt (возможно, пуст), conflict.txt (возможно, отсутствует). Также могут быть изменения в JS-файлах, если вы правили русские строки.

Закоммитьте только то, что нужно:

```bash
git add translations.txt
# Если правили русские строки:
# git add icon-theme-toolkit.js theme.js settings.js icon-compiler.js winico2linuxtheme.js
git commit -m "Translate: add N new strings"
git push
```

Не коммитьте untranslated.txt, translated.txt, dupes.txt, conflict.txt, *.bak.* — это временные файлы. Добавьте их в .gitignore:

```
untranslated.txt
translated.txt
dupes.txt
conflict.txt
translations.txt.bak.*
```

## 5.2. В английском репозитории

```bash
cd ../icon-theme-toolkit
git status
```

Здесь изменятся только JS-файлы (результат работы translate.awk).

```bash
git add icon-theme-toolkit.js theme.js settings.js icon-compiler.js winico2linuxtheme.js
git commit -m "Sync English translations"
git push
```

Шпаргалка: всё в одну строку

Когда процесс отлажен, весь цикл можно прогнать так:

```bash
cd ~/git/icon-theme-toolkit-rus
./build-en.sh                       # 1. собрать новые строки
cat untranslated.txt                 # 2. посмотреть, что переводить
# ... вставить в переводчик, сохранить в translated.txt ...
./paste_trans.sh                     # 3. слить в translations.txt
./build-en.sh                        # 4. пересобрать английскую версию
grep -nP '[\x{0400}-\x{04FF}]' ../icon-theme-toolkit/*.js || echo "OK"
```

Частые проблемы

«Ошибка: количество непустых строк не совпадает»

paste_trans.sh увидел, что в untranslated.txt и translated.txt разное число строк. Проверьте:

```bash
grep -c -v '^[[:space:]]*$' untranslated.txt
grep -c -v '^[[:space:]]*$' translated.txt
```

Найдите, где пропущена строка. Часто переводчики склеивают короткие строки — в этом случае переводите блоками поменьше.

«Предупреждение: untranslated.txt пуст»

Нет новых русских строк. Значит, всё переведено. Если вы только что добавили строки в JS, но untranslated.txt пуст — скорее всего, строки уже есть в translations.txt (совпадают с существующими) или вы забыли запустить build-en.sh перед проверкой.

В английской версии всё ещё есть кириллица

1. Запустите ./build-en.sh ещё раз — возможно, translations.txt не был обновлён.
2. Проверьте untranslated.txt — если он не пуст, значит, часть строк не переведена. Вернитесь к этапу 2.
3. Проверьте grep конкретно ту строку, которую видите:
   ```bash
   grep -rn "Ваша русская строка" ../icon-theme-toolkit/*.js
   ```
   Если она находится в JS — значит, translate.awk её не заменил. Проверьте, что она точно есть в translations.txt (включая пробелы и знаки препинания — они должны совпадать посимвольно).

dupes.txt растёт и мешает

Это означает, что в translations.txt накопились дубликаты. Откройте его, найдите повторяющиеся русские ключи и удалите лишние английские варианты. translate.awk всегда использует первый вариант, так что случайное удаление «правильного» перевода может изменить поведение — сначала сделайте резервную копию (cp translations.txt translations.txt.bak).

conflict.txt появляется снова и снова

Вы (или переводчик) продолжаете присылать новый перевод для русского ключа, который уже есть в translations.txt с другим переводом. Варианты:

· Принять существующий: просто удаляйте conflict.txt каждый раз.
· Принять новый: вручную заменить английский вариант в translations.txt (и убедиться, что после этого conflict.txt больше не появляется).

Хочу перевести одну конкретную строку, не запуская весь цикл

1. Откройте translations.txt, найдите нужную русскую строку.
2. Если она есть — отредактируйте английский перевод.
3. Если её нет — добавьте пару «русская\nанглийская\n\n» в конец файла вручную.
4. Запустите ./build-en.sh, чтобы применить.

Хочу посмотреть, какие строки уже переведены

```bash
cat translations.txt
```

Формат: пары «русская строка, английская строка», между парами пустая строка. Это удобно читать глазами и удобно парсить.

Хочу проверить, что translate.awk не съел ничего лишнего

Запустите build-en.sh, затем сравните количество строк в русском и английском JS:

```bash
wc -l icon-theme-toolkit.js ../icon-theme-toolkit/icon-theme-toolkit.js
```

Числа должны быть одинаковыми (замена идёт построчно, без вставки/удаления строк). Если различаются — что-то пошло не так, проверьте untranslated.txt и translations.txt.

---

Философия процесса (кратко)

1. Русский JS — источник истины. Вы правите только его. Английский JS — генерируется.
2. translations.txt — единственный источник пар «русский → английский». Он версионируется в git. Всё остальное (untranslated.txt, translated.txt, dupes.txt, conflict.txt, бэкапы) — временное.
3. translate.awk идемпотентен. Запуск несколько раз подряд даёт одинаковый результат. Если что-то пошло не так, просто запустите build-en.sh заново — английская версия перезапишется.
4. paste_trans.sh защищает от порчи translations.txt. Он не добавляет пары с уже существующим ключом, делает бэкап и пишет конфликты в отдельный файл для ручного разбора.
5. Дедупликация — постепенная. Сначала dupes.txt показывает все дубликаты. Вы разбираете их вручную, когда удобно. conflict.txt показывает только новые конфликты, появившиеся при попытке добавить пару, — это уже точечная работа.

---

Если что-то пошло совсем не так

```bash
# Откатить translations.txt к последнему бэкапу
ls -1t translations.txt.bak.* | head -1
cp translations.txt.bak.20251031-153000 translations.txt

# Пересобрать английскую версию с чистого листа
./build-en.sh
```

Если сомневаетесь — сделайте git status и git diff в обоих репозиториях, чтобы увидеть, что изменилось. git checkout -- файл откатит конкретный файл к последнему коммиту.
